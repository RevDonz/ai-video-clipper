## 2. Library dan struktur file

### 2.1 Pilihan

`use-intl@4.14.9` (MIT), dipin persis di `web/package.json` (`"use-intl": "4.14.9"`, tanpa `^`). **Bukan** `next-intl`, karena:
- tidak perlu routing berprefix (§6);
- `next-intl` membawa `@swc/core` (native), `@parcel/watcher`, plugin extractor, dan wajib membungkus `next.config.mjs` (yang memuat header COOP/COEP editor).

use-intl **tidak punya integrasi RSC**. Aturannya: server component memakai `createTranslator` lewat glue `getT`, client component memakai `useTranslations`.

DevDependency: `@babel/parser` (MIT, dipin persis) hanya untuk tes `i18n-hardcoded` dan `i18n-usage`. Tidak dipakai saat runtime. `next/dist/compiled/*` dilarang (internal).

Lisensi yang ditambahkan ke `/licenses` (test-first, tes lisensi yang sudah ada diperluas): `use-intl`, `intl-messageformat`, `@formatjs/*` (yang ditarik), `icu-minify`, `@schummar/icu-type-parser`. `@babel/parser` tidak dikirim ke klien, jadi tidak masuk `/licenses`.

Kolom DB yang dipakai dokumen ini **bukan** file dokumen ini: `users.locale` ada di `0001-identity.sql` (01 §4.1), `invites.locale` di file yang sama, `users.time_zone` di `0006-user-time-zone.sql` (01 §4.6).

**Satu katalog per locale = satu folder** `web/messages/<code>/`, dipecah per namespace supaya rute hanya memuat namespace yang dipakai (editor tidak memuat `help`, dashboard tidak memuat `editor`) dan diff review kecil. `catalog.mjs` memuat file dengan `import()` dinamis berpola literal (`import(\`../../messages/${code}/${ns}.json\`, { with: { type: "json" } })`) yang ter-bundle oleh Next; `code` dan `ns` selalu divalidasi terhadap registry dan daftar `NAMESPACES` (konstanta beku di `catalog.mjs`) sebelum dipakai, jadi tidak ada path dari input pengguna. Hasil di-cache per `(code, ns)` di memori proses.

## 3. Registry locale

`web/lib/i18n/locales.mjs` **(baru)**:

```js
export const LOCALES = Object.freeze([
  Object.freeze({ code: "id", intl: "id-ID", label: "Bahasa Indonesia", dir: "ltr" }),
  Object.freeze({ code: "en", intl: "en-US", label: "English",          dir: "ltr" }),
]);
export const DEFAULT_LOCALE = "id";              // sumber kebenaran copy; tidak bisa dimatikan
export const SOURCE_LOCALE = "id";

// POTONGIN_LOCALES="id" | "id,en" | ... ; default "id". Dibaca saat runtime (bukan saat build).
export function enabledLocales(env = process.env) { /* parse, buang kode tak dikenal, selalu sisipkan "id" di depan */ }
export function localeEntry(code) { /* entri registry atau null */ }
export function isEnabled(code, env = process.env) { /* code ∈ enabledLocales(env) */ }
```

Aturan:
- `label` ditulis dalam bahasanya sendiri (endonim), tidak diterjemahkan.
- `dir` disiapkan untuk bahasa RTL di masa depan; semua CSS memakai properti logis (`margin-inline-*`) di layar yang ditulis ulang. Locale RTL pertama butuh audit layout tersendiri (di luar lingkup).
- Kode di `POTONGIN_LOCALES` yang tidak ada di registry: diabaikan, dan `i18n-registry` gagal di CI kalau `.env.example` atau `compose.yaml` memuat kode tak dikenal.
- Locale nonaktif yang diminta (cookie/DB/header) diperlakukan seperti tidak ada → lanjut ke langkah resolusi berikutnya.
- Pseudo-locale `qps` (teks dibungkus `［…］` dan diperpanjang ±35%) **hanya** di dev lewat `POTONGIN_I18N_PSEUDO=1`; tidak pernah masuk `LOCALES`.

Flag `POTONGIN_LOCALES`:
- `compose.yaml` service `app`, blok `environment`: `POTONGIN_LOCALES: ${POTONGIN_LOCALES:-id}` (compose menulis env per service secara eksplisit, jadi `.env` saja tidak sampai).
- `.env.example`: `POTONGIN_LOCALES=id` dengan komentar "Bahasa UI aktif, dipisah koma. id selalu aktif."
- Dijaga `web/tests/env-example.test.mjs` dan `deploy-env-contract` (02 §13).
- `primary-worker`, `social-worker`, `render-worker` **tidak** menerima flag ini (worker tidak tahu bahasa UI).

## 4. Menambah bahasa baru (contoh: `ms`, Bahasa Melayu)

Janji pemilik "1 JSON + 1 baris registry" diwujudkan sebagai **1 katalog + 1 baris registry**. Tidak ada perubahan kode lain.

1. Salin katalog sumber: `cp -r web/messages/id web/messages/ms`.
2. Terjemahkan nilai di semua file `web/messages/ms/*.json`. Kunci tidak diubah. Bentuk plural mengikuti kategori `Intl.PluralRules("ms-MY")` (tes memberi tahu kategori yang wajib).
3. Tambah satu baris di `web/lib/i18n/locales.mjs`:
   ```js
   Object.freeze({ code: "ms", intl: "ms-MY", label: "Bahasa Melayu", dir: "ltr" }),
   ```
4. Jalankan tes yang ditargetkan (dari folder `web/`): `node --test tests/i18n-catalog.test.mjs tests/i18n-registry.test.mjs tests/i18n-error-codes.test.mjs`. Tes gagal dengan daftar kunci yang hilang/ICU rusak/kategori plural salah sampai katalog lengkap.
5. Kalau ada label React Aria/HeroUI yang tidak tersedia untuk `ms`, tidak perlu apa-apa: semua label bawaan sudah ditimpa dari namespace `aria` (§12).
6. Nyalakan di produksi: `POTONGIN_LOCALES=id,en,ms` di `.env` VM, deploy ulang (tanpa rebuild image).

Yang otomatis ikut: pemilih bahasa (membaca `LOCALES` aktif), resolusi `Accept-Language`, `<html lang>`, format tanggal/angka (`intl`), metadata, email, `global-error.jsx` (impor dinamis §8.5), kolom `users.locale` (tanpa FK/enum, §9.4). Tidak ada perubahan di `next.config.mjs`, `proxy.js`, URL, atau file tes.

Yang **tidak** ikut otomatis dan harus diputuskan per bahasa: apakah engine mendukung bahasa itu sebagai **bahasa video** (itu daftar terpisah `VIDEO_LANGUAGES` di `web/lib/jobs.mjs`, bukan i18n).

## 5. Resolusi locale

### 5.1 Urutan

| Prioritas | Sumber | Kapan dipakai |
|---|---|---|
| 1 | `users.locale` | Saat server sudah memegang objek user (login, `/api/locale`, route/halaman yang memanggil `requireUser`/`sessionFromCookieStore`). Sejak M6a. |
| 2 | Cookie `potongin_locale` | Setiap request. Sumber utama per request. |
| 3 | `Accept-Language` | Hanya kalau cookie tidak ada atau tidak valid. |
| 4 | `id` | Selalu ada. |

Setiap kandidat harus `isEnabled()`; kalau tidak, lanjut ke prioritas berikutnya. `proxy.js` **tidak** membaca DB dan tidak menyentuh locale.

**Tidak ada baca DB tambahan per request.** `users.locale` disalin ke cookie saat login, sehingga pada praktiknya cookie selalu mencerminkan DB untuk perangkat itu. Perubahan bahasa di perangkat A sampai ke perangkat B pada login berikutnya di B (perilaku yang disengaja, dicatat di Bantuan → Akun).

### 5.2 Cookie

`web/lib/i18n/cookie.mjs` **(baru)**:

```
potongin_locale=<code>; Path=/; Max-Age=31536000; SameSite=Lax; Secure
```

- **Tidak HttpOnly**: `global-error.jsx` membaca `document.cookie` (dia tidak bisa memanggil server). Nilainya bukan rahasia.
- `Secure` selalu ditulis, sama dengan `sessionCookie()` di `web/lib/auth.mjs:72` (Chromium menganggap `localhost` aman, jadi e2e lokal tetap jalan).
- Nama tanpa prefix `__Host-` (prefix itu tidak menambah keamanan untuk nilai non-rahasia dan menyulitkan dev).
- Nilai selalu divalidasi terhadap registry saat dibaca; nilai asing diabaikan (tidak dihapus).

### 5.3 `Accept-Language`

`parseAcceptLanguage(header, enabled)` di `web/lib/i18n/resolve.mjs`:

1. Header > 512 karakter atau tidak ada → `null`.
2. Pecah dengan `,`, ambil paling banyak 32 entri. Tiap entri: `tag[;q=x]`. `q` tidak valid → 1; `q=0` dibuang; `*` dibuang.
3. Tag di-lowercase, ambil subtag utama (`en-GB` → `en`). Alias: `in` → `id`.
4. Urutkan stabil berdasarkan `q` turun (urutan asli memecah seri).
5. Kembalikan subtag pertama yang ada di `enabled`, atau `null`.

Contoh (enabled = `id,en`): `en-GB,en;q=0.9` → `en`; `ms-MY,in;q=0.8` → `id`; `fr-FR` → `null` → `id`; `en;q=0, id` → `id`.

### 5.4 API server

`web/lib/i18n/server.mjs` **(baru)**:

```js
// Dipanggil hanya dari server component / route handler.
export async function getLocale({ user } = {}) // user?.locale > cookies() > headers() Accept-Language > "id"
export async function getT(locale, namespace)   // createTranslator({ locale: entry.intl, messages, namespace, onError, getMessageFallback })
export async function messagesFor(locale, namespaces) // objek gabungan, sudah di-fallback ke id
export function getFormat(locale, timeZone)     // createFormatter({ locale: entry.intl, timeZone, now })
export async function getTimeZone({ user } = {}) // §13
```

`getLocale()` memanggil `cookies()` dan `headers()` dari `next/headers`. Akibatnya **semua rute menjadi dynamic** (termasuk landing `/` yang sekarang statis). Ini diterima:
- respons HTML diberi `Cache-Control: private, no-store` lewat entri baru di `async headers()` `web/next.config.mjs` (sekarang hanya berisi entri editor di baris 28): `{ source: "/((?!_next/|api/|favicon\\.ico).*)", headers: [{ key: "Cache-Control", value: "private, no-store" }] }`, ditambah `Vary: Cookie, Accept-Language`. Entri editor yang ada tetap dan juga mendapat header ini (keduanya cocok; header berbeda kunci tidak bentrok);
- `getTimeZone()` sebelum M7b selalu mengembalikan `"Asia/Jakarta"` (belum ada `users.time_zone`); tanggal yang bergantung zona perangkat (relatif, jadwal) dirender di klien;
- TTFB `/`, `/dashboard`, `/login` diukur sebelum dan sesudah M0 dan dicatat di PR;
- `deploy/VM_NGINX_CLOUDFLARE.md` mendapat catatan: jangan cache HTML di edge; cache-key tidak boleh mengabaikan cookie.

## 6. URL tanpa prefix locale

URL tidak berubah per bahasa (`/dashboard`, bukan `/en/dashboard`). Alasan:

1. **COOP/COEP editor**: rute editor punya header isolasi sendiri di `next.config.mjs`; prefix menggandakan semua pola header dan matcher.
2. **`editorHref`** dan semua tautan ke editor dirender sebagai `<a>` dengan pemuatan penuh (tanpa `RouterProvider`); prefix memaksa setiap pembuat tautan tahu locale.
3. **Matcher `proxy.js`** memakai regex path; prefix menggandakan semua pengecualian.

### 7.2 Penamaan kunci

- Bentuk `namespace.area.item`, segmen dalam **camelCase**: `dashboard.composer.submit`, `editor.advanced.summary`.
- **Pengecualian**: segmen kode error dan kode tahap ditulis **persis** seperti kodenya (snake_case): `errors.edit.range_invalid`, `errors.editor_ai.rate_limited`, `stage.transcribe_audio`. Kunci error = `"errors." + messageId` tanpa transformasi.
- Kode yang membawa detail (`glyph_unsupported:U+1F602`): kunci memakai bagian sebelum `:` (sama dengan `base_code()` Python); bagian sesudahnya dikirim sebagai parameter `{detail}`.
- Kunci tidak boleh mengandung `.` di dalam segmen (use-intl memakai `.` sebagai pemisah). Tes `i18n-catalog` menolaknya.
- Kunci ditulis sebagai **literal penuh** di `t("…")`. Kunci dinamis hanya lewat helper yang daftar kodenya diuji lengkap: `errorText`, `stageText`, `reasonText`, `statusText`, atau map eksplisit `{ [code]: "key.literal" }`.
- Kunci yatim (tidak dipakai) dilarang, kecuali subtree yang diisi helper kode (`errors.*`, `hints.*`, `stage.*`, `reason.*`, `status.*`, `aria.*`, `meta.*`).

### 7.3 ICU: plural, select, rich text

Kalimat tidak pernah dirakit dari potongan. Contoh pasangan `id` / `en`:

```json
// web/messages/id/projects.json
{ "list": {
    "clipCount": "{count, plural, other {# klip}}",
    "summary": "{language} · {resolution}",
    "deleted": "{count, plural, other {# proyek dihapus}}"
} }
// web/messages/en/projects.json
{ "list": {
    "clipCount": "{count, plural, one {# clip} other {# clips}}",
    "summary": "{language} · {resolution}",
    "deleted": "{count, plural, one {# project deleted} other {# projects deleted}}"
} }
```

- Bahasa Indonesia hanya punya kategori `other`; Inggris `one` + `other`. Tes membandingkan kategori dengan `new Intl.PluralRules(intl).resolvedOptions().pluralCategories`. `=0` boleh dipakai di semua bahasa untuk keadaan kosong.
- `select` untuk varian non-angka: `"{platform, select, youtube {YouTube} tiktok {TikTok} instagram {Instagram} other {{platform}}}"`.
- Rich text dengan `t.rich` (tag `<link>`, `<b>`, `<kbd>`); markup HTML mentah di katalog dilarang.
- Ringkasan disclosure **Lanjutan** editor memakai `useFormatter().list(items, { type: "unit" })`, bukan gabungan string manual: `editor.advanced.summary` = `"{items}"` dengan `items` dari label pendek tiap nilai yang berbeda dari default (contoh id: "Ukuran 64 · Posisi bawah", en: "Size 64 · Position bottom"). Separator ` · ` ditentukan sekali di `format.mjs`.
- Panjang: label EN tidak boleh lebih dari 1,3× panjang label ID untuk tombol dan tab (tes `i18n-catalog` memberi peringatan, bukan gagal; screenshot 360 px yang menjadi gate).

### 7.4 Fallback

- Saat memuat, katalog locale `X` di-**deep-merge di atas** katalog `id` (`catalog.mjs`). Kunci yang hilang di `X` tampil dalam Bahasa Indonesia.
- `onError` di produksi: log sekali per `(locale, key)` per proses (`console.warn` dengan prefix `[i18n]`), tanpa melempar.
- `getMessageFallback` (kalau kunci juga tidak ada di `id`): menampilkan teks netral dari `common.unavailable` ("—"), bukan nama kunci.
- Di tes (`NODE_ENV=test` atau `POTONGIN_I18N_STRICT=1`): `onError` **melempar**, jadi kunci hilang membuat tes gagal. Playwright menjalankan server dengan `POTONGIN_I18N_STRICT=1`.

### 7.5 Aturan copy (semua bahasa)

- Label, bukan kalimat. Tanpa basa-basi, tanpa teks pengisi, tanpa kata versi/"baru"/"Selection V3" (dijaga `ui-guards` di semua locale).
- Huruf: kapital awal kalimat (sentence case) di ID dan EN. EN tidak memakai Title Case.
- Istilah wajib dari glosarium (§16). Istilah yang dipertahankan lintas bahasa: Potongin, Hook, Cold open, Logo, Audio, YouTube/TikTok/Instagram.

- menulis `<html lang={code}>`.

### 9.2 Kontrak `POST /api/locale`

File: `web/app/api/locale/route.js` **(baru)**, `export const runtime = "nodejs"`.

| Aspek | Nilai |
|---|---|
| Method | `POST` saja. Method lain → 405 dengan header `Allow: POST`. |
| Auth | **Publik.** Dikecualikan dari matcher `proxy.js` (tambah `api/locale/?$`). Sejak M6a: kalau ada sesi valid, route memeriksa sesi sendiri lalu juga menulis `users.locale`. |
| Origin | `sameOriginMutation(request)` wajib; gagal → 403. |
| Body | `application/x-www-form-urlencoded` (form native) atau `application/json` `{ "locale": "en" }` (opsional untuk klien JS; form tetap jalur utama). Urutan baca: (1) header `Content-Length` > 1024 → 413 sebelum membaca body; (2) form → `readBoundedUrlEncodedForm(request, 1024)`; helper ini melempar error yang sama untuk body rusak dan body > 1024 tanpa `Content-Length`, keduanya dijawab 400 `invalid_request`; (3) JSON → baca maksimal 1024 B, lebih → 413, gagal parse → 400. Field form: `locale` (wajib), `next` (opsional, path). Content-Type lain → 400. |
| Validasi | `locale` ∈ `enabledLocales()`; selain itu 400 `locale_unsupported`. |
| Rate limit | Baris kind `locale` di tabel 02 §7.1 merujuk ke sini. Modul-level di route: `new TokenBucketLimiter({ capacity: 20, refillPerSecond: 20 / 60, maxKeys: 10_000 })` dari `web/lib/rate-limit.mjs` (20/menit); kunci = `"locale:" + sha256hex(trustedClientIp(request) ?? "untrusted-proxy-client")`. Ditolak → 429 + `Retry-After: retryAfterSeconds(retryAfterMs)`. Urutan cek: method → origin → rate limit → body. |
| Efek | `Set-Cookie: potongin_locale=<code>; …` (§5.2). Sejak M6a, bila sesi valid (`currentUser(request)` 01 §2.3, sinkron): `UPDATE users SET locale = ?, updated_at = ? WHERE id = ?` di dalam `tx()` (kolom di 01 §4.1; `updated_at` epoch ms seperti kolom `*_at` lain). Sesi tidak valid/tidak ada → cookie saja, tanpa error. Diizinkan juga saat `must_change_password=1` (allowlist 02 §6.5). |
| Respons form | `303 See Other`, `Location` = (a) `next` bila `safeNextPath(next) === next` (nilai tidak diubah helper); (b) kalau tidak, `pathname+search` dari `Referer` bila origin-nya sama dengan `Host` (diparse dengan `new URL`, lalu `safeNextPath`); (c) kalau tidak, `/`. Jangan memanggil `safeNextPath(undefined)` sebagai fallback karena hasilnya `/dashboard` (membingungkan untuk pengunjung `/login`). `Cache-Control: no-store`. |

| Status | `code` | `messageId` | Kapan |
|---|---|---|---|
| 400 | `invalid_request` | `web.invalid_request` | body tidak bisa dibaca / bukan form atau JSON |
| 400 | `locale_unsupported` | `web.locale_unsupported` | kode tidak ada di registry atau nonaktif |
| 403 | `csrf_rejected` | `web.csrf_rejected` | `sameOriginMutation` gagal |
| 405 | `method_not_allowed` | `web.method_not_allowed` | selain POST |

### 9.4 Kolom DB dan sinkron login (M6a)

Kolom `users.locale TEXT NULL` sudah ada di `0001-identity.sql` (DDL dan CHECK: 01 §4.1; dirilis Fase 4 bersama MU-M1/M2, jadi M6a **tidak** punya file migrasi sendiri). Aturan pakainya (milik dokumen ini):

- `NULL` = belum pernah memilih. Nilai tidak di-FK ke registry (registry ada di kode); validasi pola dan keanggotaan registry dilakukan JS saat tulis; kode yang tidak lagi ada di registry diperlakukan seperti `NULL`.
- **Saat login sukses** (`POST /api/auth/login`, 02 §6.1 langkah 4): kalau `users.locale` valid dan aktif → tulis cookie `potongin_locale` = nilai itu. Kalau `NULL` → isi `users.locale` dari cookie yang valid, atau dari `Accept-Language`, atau `id`; lalu tulis cookie.
- **Saat logout**: cookie bahasa **tidak** dihapus (perangkat tetap berbahasa sama di halaman login).
- **Undangan** (M7a, alur dan API milik 02 §6.3): admin memilih `locale` di `POST /api/admin/invites` (default = locale admin), disimpan di `invites.locale`. Halaman `/undangan/[token]` dirender dalam bahasa itu kecuali pengunjung sudah punya cookie; pemilih bahasa di form terima undangan default ke `invites.locale`, dan `POST /api/auth/invite/accept` menulis pilihan form ke `users.locale`.
- **Rollback**: image lama mengabaikan kolom dan cookie → UI Indonesia.

## 10. Error server → teks klien

### 10.1 Kontrak (aditif, CONTRACTS §5.65)

- Setiap route **mempertahankan bentuknya** sesuai CONTRACTS:
  - datar: `{ "error": "<teks id>", "code": "<code>", "messageId": "<domain>.<code>", "params"?: {…} }`
  - bersarang: `{ "error": { "code": "<code>", "messageId": "<domain>.<code>", "params"?: {…}, …field lama } }`
- Route yang sekarang hanya mengirim string mendapat tambahan `code`, `messageId`, `params?` dengan **bentuk datar**. String `error` Indonesia **tetap ada** (untuk log, agen Hermes `api/ingest/trends`, dan image lama saat rollback). Tidak ada rencana menghapusnya.
- `params` hanya berisi nilai primitif (string/number), maksimal 8 kunci, tanpa teks bebas dari pengguna yang belum di-escape (ICU tidak mengeksekusi markup, tetapi `t.rich` tidak dipakai untuk params server).
- Contoh datar (dari `proxy.js`, diperluas):
  ```json
  { "error": "Sesi login diperlukan", "code": "unauthorized", "messageId": "web.unauthorized" }
  ```
- Contoh bersarang (preview-lane, tidak berubah selain field opsional):
  ```json
  { "error": { "code": "backend_unavailable", "messageId": "edit.backend_unavailable" } }
  ```
- Contoh berdetail:
  ```json
  { "error": "Karakter tidak didukung font", "code": "glyph_unsupported:U+1F602", "messageId": "edit.glyph_unsupported", "params": { "detail": "U+1F602" } }
  ```

### 10.2 Domain dan registry kode

### 10.3 Klien

`web/lib/api-error.mjs` **(baru)**:

```js
// Menerima body JSON apa pun (string, datar, bersarang) + status HTTP.
export function normalizeApiError(body, status) // → { code, messageId, params, legacyText, status }
```

Aturan normalisasi: bersarang → ambil `body.error.{code,messageId,params}`; datar → `body.{code,messageId,params}`, `legacyText = body.error`; string → `legacyText`; tanpa body → `messageId = "http.s" + status`. `code` berdetail dipecah dengan `splitDetail()` → `params.detail`.

## 13. Tanggal, angka, waktu, zona (jadwal)

### 13.1 Format UI

- Semua tanggal, angka, ukuran file, detik editor (`TranscriptPanel`, `TextPanel`, `CleanupReview`, `transcript/model.mjs`), jam `ExportDialog`, `notation: "compact"`, `Intl.DisplayNames` memakai `useFormatter()` (klien) atau `getFormat(locale, timeZone)` (server), dengan `localeEntry(locale).intl`.
- Konstanta modul seperti `const SECONDS = new Intl.NumberFormat("id-ID")` diganti cache per locale di `web/lib/i18n/format.mjs` (`numberFormat(intl, options)` memoized).
- Format jam: **24 jam di semua locale** (`hourCycle: "h23"`) *(Q8 default, bisa diubah)*.
- Waktu relatif ("3 menit lalu") dirender di klien dengan `now` dari server (prop `now` di `IntlProvider`) untuk menghindari hydration mismatch.

### 13.2 Zona waktu (M7b, Fase 8)

| Aspek | Nilai |
|---|---|
| Kolom | `users.time_zone TEXT NULL` dari `0006-user-time-zone.sql` (DDL: 01 §4.6). Saat tulis, JS memvalidasi nilai terhadap `Intl.supportedValuesOf("timeZone")` + `"UTC"` |
| Default | `NULL` → zona browser yang dikirim sekali oleh klien (§13.3) → fallback `Asia/Jakarta` |
| API | Route `PATCH /api/account/preferences` (method, guard, body ≤ 1 KiB, patch parsial, dan error: 02 §8.2). M7b menambah field `timeZone`: body JSON `{ "timeZone": "Asia/Makassar" }` → `200` preferensi lengkap; nilai tidak valid → 400 `account.time_zone_invalid`. Aturan nilai (IANA + `"UTC"`) dan header `X-Potongin-Auto` (§13.3) milik dokumen ini. Bahasa **tidak** lewat route ini; tetap `/api/locale`. |
| Isi UI | Field "Zona waktu" (`ComboBox` IANA, layar 05 §6.11) di `/akun`, sejak Fase 8 |
| Provider | `getTimeZone({ user })` → `IntlProvider timeZone` + `getFormat(locale, timeZone)` |

### 13.3 Deteksi zona perangkat

Saat `users.time_zone` `NULL`, `AppShell` mengirim `Intl.DateTimeFormat().resolvedOptions().timeZone` **sekali** per sesi ke `PATCH /api/account/preferences` (body `{ timeZone }`) dengan header `X-Potongin-Auto: 1` (server hanya menulis bila kolom masih `NULL`, sehingga pilihan manual tidak tertimpa).

### 13.4 Jadwal posting

- Input: HeroUI `DatePicker` + `TimeField` dengan `ZonedDateTime` (`@internationalized/date`), `granularity="minute"`, `hourCycle={24}`. **Nama zona pendek ditampilkan** (tidak memakai `hideTimeZone`), misalnya "WIB" / "GMT+7".
- Dikirim: `when = { mode: "at", at: "<ISO UTC>", tz: "<IANA>" }` ke API sosmed (03 §9.1); `at` = `ZonedDateTime.toAbsoluteString()`. Disimpan (03 §4.2 / 01 §4.5): `scheduled_at` (INTEGER ms epoch UTC) + `scheduled_tz` (IANA zona saat dijadwalkan); respons `Run` memuat `scheduledAt` (ISO) + `scheduleTz`. Tidak ada waktu lokal tanpa zona di DB.
- Tampil: dikonversi ke zona penonton; kalau beda dengan `scheduleTz`, tampilkan juga waktu asal sebagai teks sekunder (`social.schedule.originalTime` = `"{time} ({zone})"`).
- DST: input yang jatuh di celah DST ditolak di klien dan server dengan 422 `social_time_nonexistent` (kode milik 03 §8; kunci `errors.social.social_time_nonexistent`); yang ambigu memilih offset lebih awal (`disambiguation: "earlier"`) dan menampilkan offset-nya.
- Tes: jam manual (`now` diinjeksi) dengan zona `America/Los_Angeles` di sekitar pergantian DST; jadwal yang dibuat di `en` zona X tampil benar di `id` zona Y (e2e `social-publish.spec` di dua locale).

| Risiko | Mitigasi |
|---|---|
| Churn ±1.400 literal + prosa Bantuan selagi layar dirombak | Kunci dibuat saat layar ditulis ulang; ratchet per file |
| Copy `en` panjang merusak 360 px / 1366×768 | Aturan label semua bahasa; `qps` di dev; screenshot `en` per fase |

| Locale UI bocor ke engine/LLM/render | `content-language-isolation`; `videoLanguage` satu-satunya sumber bahasa konten |
| Perubahan error mematahkan klien/agen/rollback | Aditif saja; `error` string tetap; `api-error.mjs` |
| Semua rute dynamic, cache edge salah bahasa | Ukur TTFB; `private, no-store`; catatan nginx/Cloudflare |
